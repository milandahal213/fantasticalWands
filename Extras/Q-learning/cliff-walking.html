Cliff Walking: Q-learning vs SARSA

Same environment, same reward, two algorithms — and two very different learned routes.

The setup

A long strip of grid: the tank starts at the bottom-left, the goal (flag) is at the bottom-right, and the entire bottom row between them is a cliff. Stepping onto the cliff costs a large penalty and sends the tank straight back to the start — but the episode keeps going, it doesn't end. Every ordinary step costs a small penalty too, so the fastest route (right along the cliff edge) is tempting, but risky whenever an exploring step accidentally goes the wrong way.

Q-learning updates using max(Q(s′)) — the value of the best possible action from wherever it lands, regardless of what it actually does next. SARSA updates using Q(s′,a′) — the value of whatever action it actually takes next, exploration included. That difference sounds small, but it changes which route each algorithm considers "safe."

Try this

1. Train Q-learning for at least 1500–2000 episodes (the default in the box), then switch to SARSA and train it the same amount — a few hundred isn't quite enough for either policy to fully settle.
2. Click "Compare both paths" — Q-learning's route (blue) tends to hug the cliff edge, the shortest possible path; SARSA's route (green) tends to take a detour a row or two further from the edge.
3. Here's why: Q-learning always updates toward the best action from the next state, so it learns the value of the optimal path even while its own exploring steps occasionally fall off. SARSA updates toward the action it actually takes next — including the random exploratory ones — so walking right along the edge looks worse to it, since a random slip while training there is genuinely costly to its own experience.
4. Raise ε and retrain both — the gap between the two routes should widen, since more exploration means more accidental cliff falls for SARSA to factor into its own path's value.
